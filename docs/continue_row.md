# «Продолжить» первым пунктом в консоли

Дата: 2026-11-26. Реализовано и проверено на консоли.

## Что делает

В списке игр внутри `Roms/<консоль>` первой строкой появляется **последняя
игра, в которую вообще играли**, — но только если она из этой консоли.
Строка выделена белой «пилюлей» (как выбранная) и помечена стрелкой `»`;
справа — обложка этой игры.

- A на строке — запуск игры с сохранения.
- Y «ПРОДОЛЖИТЬ» внизу — тот же запуск (штатная подсказка, если сейв есть).
- Если последняя игра была в другой консоли, строки нет.
- В результатах поиска строка не участвует.

## Почему «последняя вообще», а не «последняя в этой консоли»

Перебор всей истории (`recents.txt`, до 24 записей) на каждый кадр оказался
дорогим: в консолях, где строки нет, список пересканировался постоянно.
Вариант «самая свежая запись вообще» стоит одно чтение и одно сравнение путей:

- нет цикла по истории;
- нет обращений к диску (`stat`) — читаются только поля структуры `Recent`;
- после вставки следующий кадр выходит по маркеру `alpha == -1`.

## Как определяется игра

`Recents_at(0)` — самая свежая запись истории. Если её путь лежит в текущей
папке консоли, патч находит эту игру в видимом списке (сравнение полного пути)
и вставляет её копию первой строкой.

- Для склеенных консолей (например, Game Boy + Game Boy Color) путь всё равно
  лежит в видимой папке — работает.
- Если в консоли ещё ничего не запускали или последняя игра была в другой
  консоли — строки нет.

## Реализация

- Хук в начале `GameList_handleInput` (0x41d840).
- `Recents_at(0)` (0x4acc20): `path` — без префикса `/mnt/SDCARD` (11 символов),
  `available` — байт по смещению 0x10.
- Путь записи списка — абсолютный, поэтому сравнивается `entry->path + 11`
  с путём из recents.
- У синтетической записи:
  - `name` — реальное имя игры (для `Entry_open`, recents, меню);
  - `unique` — отображаемая строка `» <игра>`;
  - `alpha = -1` — маркер нашего пункта;
  - вставка: `Array_push` + `memmove(items+1, items, n*8)`, `alphas.items[] += 1`;
  - `selected = 0`, `start = 0`, `end = min(rows, count)`.
- A на строке: хук `openSelected` (0x416810) выставляет
  `resume.should_resume = 1`, дальше штатный `Entry_open` запускает с сейва.
- Флаг dirty (0x4d7c04) — чтобы список перерисовался сразу.

## Важно для правок этого кода

`strncmp`/`strlen`/`snprintf` — обычные вызовы, они **затирают**
caller-saved регистры (x0–x18). Именно на этом был баг: длина пути хранилась в
`x15` и после `strncmp` превращалась в мусор, из-за чего проверка «путь из этой
папки» всегда проваливалась. Значения, живущие через вызов, держать только в
x19–x28.

## Ограничения

- Контекстное меню на строке действует на реальную игру (удалить,
  переименовать, обложка).
- Строка только в списках под `Roms/` (не в Tools, Collections, Recents,
  поиске и не на карусели консолей).
- Длинные названия в строке прокручиваются штатной бегущей строкой, поэтому
  `»` может уехать за край — строка всё равно первая и выделена.

## Замеры (TrimUI Brick Pro, 2026-11-26)

Замер: время от нажатия A на карусели до появления списка, и процессорное время
`nextui` в покое в списке (тики по 10 мс за 100 мс окна).

| Сборка | GB: вход | GB: покой | GBA: вход | GBA: покой |
|---|---|---|---|---|
| Сток (`7bef5587`) | 1.48–1.57 с | ~0 % | 1.52–1.68 с | ~115 % |
| Старый патч (`c49fa01`) | 1.43–1.62 с | ~0 % | 1.45–1.67 с | ~115 % |
| Новый патч (`f662cfb3`) | — | — | 1.51–1.88 с | ~115 % |

Вывод: патч не добавляет измеримой задержки. Постоянные ~115 % CPU в больших
списках (GBA/Mega Drive) — штатное поведение прошивки (отрисовка/бегущая
строка), оно есть и на стоке. Задержка входа ~1.5 с — это `Directory_new`
(чтение папки), тоже штатная.

- GB при последней игре из GBA: строки нет (ожидаемо).
