# «Продолжить» первым пунктом в консоли

Дата: 2026-11-26. Реализовано и проверено на консоли.

## Что делает

В списке игр внутри `Roms/<консоль>` первой строкой появляется **самая свежая
игра этой консоли** — то есть верхняя подходящая запись из «Недавних».
Строка выделена белой «пилюлей» и помечена стрелкой `»`; справа — её обложка.

- A на строке — обычный запуск, как из «Недавних»: если у игры есть сейв-стейт,
  он загружается (флаг `resume.should_resume = resume.can_resume`, как у
  карточки Continue на главной).
- Y «ПРОДОЛЖИТЬ» внизу — тот же запуск.
- Строки нет, если в этой консоли ещё ничего не запускали.
- В результатах поиска строка не участвует.

## Синхронизация с «Недавними»

Для каждой консоли берётся **первая** запись `recent.txt`, которая лежит в этой
папке. Поэтому в «Недавних» и в строке всегда одна и та же игра: запустил игру
в NES — строка появилась в NES, а в GB осталась своя (предыдущая GB-игра).

## Стоимость

- Перебор идёт **в памяти**: читаются только поля структур `Recent`
  (`path`, `available`), без `stat` и чтения файлов.
- Один проход на список: `Directory.serial` запоминается в хвосте BSS
  (`cont_state_va`), дальше выход по одному сравнению. Плюс маркер
  `alpha == -1` на вставленной строке.
- Замеры: вход в консоль и процессорное время в покое не отличаются от стока
  (см. таблицу ниже).

## Реализация

- Хук в начале `GameList_handleInput` (0x41d840).
- `Recents_at(i)` (0x4acc20): `path` — без префикса `/mnt/SDCARD` (11 символов),
  `available` — байт по смещению 0x10. Путь записи списка абсолютный, поэтому
  сравнивается `entry->path + 11` с путём из recents.
- У синтетической записи:
  - `name` — реальное имя игры (для `Entry_open`, recents, меню);
  - `unique` — отображаемая строка `» <игра>`;
  - `alpha = -1` — маркер нашего пункта;
  - вставка: `Array_push` + `memmove(items+1, items, n*8)`, `alphas.items[] += 1`;
  - `selected = 0`, `start = 0`, `end = min(rows, count)`.
- A на строке: хук `openSelected` (0x416810) делает
  `resume.should_resume = resume.can_resume`; дальше штатный `Entry_open`
  запускает игру (со стейтом, если он есть).
- Флаг dirty (0x4d7c04) — чтобы список перерисовался сразу.

## Грабли (важно для правок)

1. **Caller-saved регистры.** `strncmp`/`strlen`/`snprintf` затирают x0–x18.
   Длина пути жила в `x15` и после вызова превращалась в мусор — проверка
   «путь из этой папки» всегда проваливалась. Живые через вызов значения —
   только x19–x28.
2. **ADRP даёт страницу, а не адрес.** В хуке `openSelected` было
   `adrp x9, #0x50e000` и `strb ..., [x9, #1]` без `add x9, x9, #0x1d8` —
   флаг `resume.should_resume` писался в `0x50e001`, поэтому запуск с нашей
   строки не возобновлял игру. Для глобалов всегда `adrp` + `add` с
   `(addr & 0xFFF)`.
3. `e_ldr_w`/`e_str_w` требуют явного смещения (даже 0).

## Замеры (TrimUI Brick Pro, 2026-11-26)

Время — от нажатия A на карусели до появления списка; CPU — процессорное время
`nextui` в покое (тики по 10 мс за окно 100 мс).

| Сборка | GB: вход | GB: покой | GBA: вход | GBA: покой |
|---|---|---|---|---|
| Сток `7bef5587` | 1.48–1.57 с | ~0 % | 1.52–1.68 с | ~115 % |
| Старый патч `c49fa01` | 1.43–1.62 с | ~0 % | 1.45–1.67 с | ~115 % |
| Новый патч | 1.47–1.65 с | ~0 % | 1.51–1.88 с | ~115 % |

Вывод: патч не добавляет измеримой задержки. Постоянные ~115 % CPU в больших
списках (GBA/Mega Drive) — штатное поведение прошивки (отрисовка/бегущая
строка), есть и на стоке. Вход ~1.5 с — это `Directory_new` (чтение папки).

## Проверка

- Итоговая сборка: `0927a3db4d0238f00d6e14339dd778e2`.
- В GB и GBA строка своя (разные игры из «Недавних»), выделена, с обложкой.
- При запуске с нашей строки nextui пишет `/tmp/resume_slot.txt` = слот игры
  (проверено: `slot=9`), minarch его читает и удаляет — путь resume работает.
