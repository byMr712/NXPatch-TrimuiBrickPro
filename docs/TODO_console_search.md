# «Поиск игры в консоли» — состояние и план

Дата: 2026-11-26. Код в `tools/nxpatch.c` под флагом `-DCS_CONSOLE_SEARCH`
(по умолчанию выключен; штатная сборка даёт `a8f38cd0…`).

## Итог двух попыток

### Попытка 1. Своё открытие поиска из обработчика меню

Пункт меню (id 42) вызывал собственную копию `Search_open`: клавиатура, `snprintf` в
`search_query`, `Directory_new("/mnt/SDCARD/.search", 0)`, `Array_push(stack, dir)`,
`top = dir`.

Результат: клавиатура открывается, ввод работает, но после создания списка лаунчер
падал. Причина: штатное открытие поиска вклеено в `GameList_handleInput` и после
создания списка пишет в **стек-фрейм вызывающего** (`str w20,[sp,#0x8c]`,
`strb w20,[sp,#0x90]`) и вызывает `PLAT_clearLayers` / `ScrollText_clear` /
`readyResume`; из другой функции этот фрейм недоступен.

### Попытка 2. Переиспользование штатного блока (эта)

Пункт меню ставит `setenv("NX_SEARCH_ROOT", top->path)`. Хук в начале
`GameList_handleInput` (0x41d86c, после пролога, в его собственном фрейме) переносит
путь в `search_query+0x80`, сбрасывает флаг, выставляет `x19=0x50f1d0`,
`x22=x23=0x4d8000`, `w20=1` и прыгает в родной блок 0x41efd4. Фильтр врезан после
`Directory_new` (0x41f048) и оставляет только записи с префиксом пути консоли.

Результат: лаунчер **зависает** (процесс жив, экран замирает) сразу после выбора
пункта. Значит, блоку нужен не только регистровый контекст, но и состояние, которое
вычисляется по ходу `GameList_handleInput` до этого места (флаги кадра, выбранный
элемент, параметры списка).

## Вывод

Патчить поиск прыжком в середину инлайн-блока — тупиковый путь: блок слишком сильно
зависит от контекста кадра. Реальные варианты:

1. **Форк NextUI со сборкой из исходников** — добавить пункт в `romItems` и область
   поиска в `Search_open`/`Content_searchRoms` на уровне C. Единственный надёжный путь,
   но нужен сборочный стенд aarch64 (SDL2, SDL_ttf, SDK).
2. **Оставить как есть** — перевода, диалогов и зацикливания сетки достаточно; поиск
   по консоли не делать.
3. Полумера: пункт меню, открывающий **обычный** поиск (без ограничения по консоли) —
   тоже требует правки кода, но без прыжков в чужой фрейм: можно вызвать штатный блок
   из того же места, где его вызывает START (то есть подменить условие входа, а не
   прыгать в середину).

`Directory{path 0, name 8, entries 0x10, …, selected 0x8c, start 0x90, end 0x94}`;
`Array{count 0, capacity 4, items 8}`.

## Что уже сделано и работает

- Пункт «Поиск игры в консоли» корректно добавляется в меню игры (две точки вставки,
  гейт по типу записи) — эту часть можно переиспользовать в любом варианте.
- Фильтр по префиксу пути написан и проверен статически; падений не вызывает при
  вызове на готовом Directory.
- Инструмент сборки кода в кейве (эмиттеры AArch64) — в `nxpatch.c`, пригодится и для
  других патчей.
